# 16. Split M10 into M10a and M10b

Date: 2026-10-11

## Status

Accepted

## Context

With M9 done, M10 (DESIGN.md §9) is the last milestone. It bundles five largely unrelated
pieces of work:

- offline resilience
- show export and import
- deployment
- plugin authoring and publishing the SDK
- a 24-hour soak test

That is too much for one plan and one reviewable change, as M6 was (ADR 0009).

The risks differ too. Offline resilience and export/import are code with real failure modes.
A screen that goes blank when the venue network drops is the worst failure at a party. The
rest is mostly docs and packaging. The soak test only means something once the deployment it
runs on exists.

## Decision

M10 is split in two, done in order.

- **M10a: resilience and show portability.**
  - Offline resilience. A service worker caches the viewer shell, plugin modules and the
    assets the show uses. During an outage the viewer keeps the rotation going with
    `resolveTimeline` from its last state, and catches up on reconnect.
  - Show export and import: JSON plus a zip of the assets, for preparing a show before the
    party.
  - Done when a screen keeps playing through a network outage and a server restart, and
    catches up afterwards, and when an exported show imports into a fresh install and plays
    the same.
- **M10b: operations and release.**
  - Deployment: a systemd unit, an optional Docker image, and `docs/deployment.md`. It covers
    Caddy (two hosts, basic auth on the screen host), DNS, kiosk setup (`deploy/kiosk/`), and
    pinning or disabling Chromium updates.
  - Plugin authoring: `docs/plugin-authoring.md` and a template repository for third-party
    plugins. Publishing `@storbild/plugin-sdk`, with the build step ADR 0002 anticipated and
    core bundled in (ADR 0004). Reloading plugins from `STORBILD_PLUGIN_PATHS` when they
    change.
  - The soak test, last: 24 hours unattended on target-like hardware, with a forced network
    outage and a server restart during the run.
  - Done when a fresh VPS and kiosk can be set up from the docs alone, and the soak test
    passes.

Earlier ADRs that defer work to "M10" map as follows:

| Deferred item | Source | Now in |
|---|---|---|
| offline continuation and the service worker | ADRs 0005, 0006 | M10a |
| publishing `@storbild/plugin-sdk` (build step, core bundled in) | ADRs 0002, 0004 | M10b |
| reloading plugins from `STORBILD_PLUGIN_PATHS` on change | ADR 0004 | M10b |

## Consequences

- Each half can be planned in a fresh session from DESIGN.md §9 alone.
- The riskiest code lands first, and gets the most time in use before the party.
- The soak test runs on the deployment M10b documents, so it also checks those docs.
- Publishing the SDK depends on the `@storbild` npm scope being available (§11). Check that
  before M10b, because a rename touches every package.
- The external `now-playing` plugin (ADR 0015) is a natural first user of M10b's authoring
  guide and template.
